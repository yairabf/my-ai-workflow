# Implementation handoff

- **Approved plan** — Reference the exact approved revision and its originating task or local mission.
- **Target** — Identify the repository, dedicated branch, and worktree path.
- **Candidate commit** — Give the full SHA or state why no candidate exists.

## Tasks

Identify completed tasks and the changes included in the candidate. List unfinished tasks, uncommitted changes, blockers, and decisions needed, or record that all tasks are complete.

## Repair details (for a revised candidate)

Link the review requesting changes and give its reviewed SHA. For each required finding, describe the change included in the new candidate and identify the corresponding command and observed result below. Identify any outstanding correction.

## Verification

For each acceptance criterion and applicable repository check, give the command and observed result. Identify failed, skipped, or unavailable checks and the reason. Distinguish checks on uncommitted work from evidence for the candidate. Include only evidence a reviewer needs. Omit credentials and the developer's chat.
